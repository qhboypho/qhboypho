# Live Chat Phase 1 Spec

## Goal

Add a production-friendly live chat channel for QH Boypho that works on Cloudflare and gives admins enough context to answer product questions quickly.

## Requirements

- Logged-in customers can start chat from the storefront without re-entering contact info.
- Guest customers must enter a phone number before chat starts.
- Chat launched from a product detail view sends a compact product context card into the conversation.
- Chat also exposes a product picker so customers can send another product card later.
- Admin dashboard has a live chat inbox where all admins can see and answer conversations.
- Admin dashboard plays an audible notification when a new customer message arrives.
- Chat history is retained for 7 days, then automatically deleted.
- The design must keep payOS/payment behavior unchanged.

## Cloudflare Direction

- Use one Durable Object room per conversation for realtime WebSocket fan-out.
- Store canonical conversation and message history in D1.
- Use Durable Object WebSocket Hibernation so idle connections do not keep billing duration running.
- Keep the schema ready for multi-admin assignment, but phase 1 can expose one shared inbox to all admins.

## Data Retention

- Every live chat conversation and message gets an `expires_at` timestamp.
- A scheduled cleanup handler deletes expired records.
- Admin can still use the dashboard normally if cleanup has not run yet; reads filter expired records out.

## Acceptance

- Customer can open chat from product page and admin sees the product context.
- Guest customer cannot start chat until phone number is entered.
- Customer and admin messages persist and appear after refresh.
- Admin hears a short sound for new customer messages when the live chat page is open.
- Build passes and contract test verifies all route/config/UI integration points.
